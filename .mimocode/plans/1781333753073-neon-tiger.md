# Plan: 三平台安装包打包方案（Tauri + 渐进原生化）

## 目标

将 Studio Arona 打包为 macOS (DMG)、Windows (NSIS/MSI)、Linux (deb/AppImage) 原生安装包，用户双击即可安装使用。

## 当前状态

✅ 计划已完善，等待用户确认后开始实施。

**关键技术决策**：
- ✅ 技术选型：Tauri v2（非 Electron）
- ✅ 服务架构：分层启动 + sidecar
- ✅ 前端策略：React 不变，渐进式原生化
- ✅ 数据库：内嵌 PG/Redis 二进制

## 分阶段策略

### Phase 1：Tauri 快速交付（当前）
- **目标**：快速推出可用的桌面应用
- **技术栈**：Tauri v2 + Rust 后端 + 系统 WebView + React 前端
- **周期**：1-2 个月
- **优势**：跨平台一套代码，前端零改动，包体小

### Phase 2：渐进式原生化（未来按需）
- **目标**：将高频交互页面替换为原生 UI
- **技术栈**：
  - macOS：SwiftUI + WKWebView（混合模式）
  - Windows：WinUI 3 + WebView2（混合模式）
- **策略**：
  1. 先原生化**设置页面**（配置、模型管理）
  2. 再原生化**系统托盘/菜单**
  3. 最后考虑**仪表盘/聊天**（3D 渲染仍用 WebView）
- **优势**：渐进式迁移，不影响已发布版本

### 原生化优先级

| 页面 | 原生化优先级 | 原因 |
|------|-------------|------|
| 设置/配置 | ⭐⭐⭐ 高 | 简单表单，SwiftUI/WinUI 原生体验好 |
| 系统托盘/菜单 | ⭐⭐⭐ 高 | Tauri 已原生，仅需优化交互 |
| 登录/注册 | ⭐⭐ 中 | 简单表单，可原生 |
| RSS/Feed 阅读 | ⭐⭐ 中 | 列表为主，可原生 |
| VM/系统监控 | ⭐ 低 | 图表为主，WebView 更合适 |
| 3D 角色/聊天 | ⭐ 低 | Three.js/Spine 需要 WebView |
| 记忆/技能管理 | ⭐ 低 | 复杂 UI，WebView 更合适 |

## 技术选型：Tauri v2

### 为什么选 Tauri 而不是 Electron

| 维度 | Tauri v2 | Electron |
|------|----------|----------|
| 基础包体 | ~10MB | ~150MB+ |
| 渲染引擎 | 系统 webview (WebKit/WebView2) | 内嵌 Chromium |
| 内存占用 | 低 (共享系统 webview) | 高 (每个窗口一个 Chromium) |
| 后端语言 | Rust (高性能，内存安全) | Node.js |
| 原生能力 | 托盘、自动更新、侧车进程 | 同上 |
| 跨平台 | macOS / Windows / Linux | 同上 |
| 移动端 | iOS / Android (v2 支持) | 不支持 |
| 学习成本 | 需要 Rust 基础 | 仅 TypeScript |

**结论**：Tauri 包体小 15 倍、内存省 3-5 倍，Rust 后端更适合进程管理。前端 React 代码几乎零改动。

### 为什么不用其他方案

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| PyOxidizer 编译 Python | 消除 Python 运行时 | C 扩展兼容性差，构建复杂 | ❌ |
| pkg 编译 Node.js | 消除 Node 运行时 | 原生模块问题多 | ❌ |
| Rust 重写全部服务 | 最原生 | 工作量巨大（月级），重写已有稳定代码 | ❌ |
| 单进程架构 | 无 IPC 开销 | 需大幅重构，故障隔离差 | ❌ |
| **Tauri + sidecar** | **兼容性最佳，工作量适中** | 需捆绑运行时（~70MB） | ✅ **选择** |

**核心理由**：现有 Python/Node 服务已稳定工作，目标是打包分发而非重写。VS Code 也捆绑 Node.js，这是业界成熟方案。Tauri 的 Rust 后端高效管理进程，Python/Node 作为 sidecar 保持不变。

### 系统 webview 兼容性

| 平台 | webview | 最低版本 | 备注 |
|------|---------|----------|------|
| macOS | WebKit (Safari) | macOS 10.15+ | 原生内置 |
| Windows | WebView2 (Edge Chromium) | Win10 1803+ | 自动安装，95%+ 覆盖率 |
| Linux | webkit2gtk | Ubuntu 20.04+ | 多数发行版已预装 |

## 服务架构设计

### 设计原则

**性能优先**：最小化启动时间、内存占用、进程数量。
**兼容性优先**：保持现有服务代码不变，仅替换进程管理方式。

### 推荐架构：分层启动 + 按需加载

```
Tauri App (Rust 主进程)
  │
  ├─ Layer 0: 基础设施（必须最先，串行）
  │   ├─ PostgreSQL (内嵌二进制)
  │   └─ Redis (内嵌二进制)
  │
  ├─ Layer 1: 核心服务（PG 就绪后并行启动）
  │   ├─ API Gateway (Python, 8080) ← 前端依赖
  │   └─ alembic upgrade head
  │
  ├─ Layer 2: 智能服务（Layer 1 就绪后并行启动）
  │   ├─ LLM Gateway (Python, 8645)
  │   ├─ Agent Bridge (Node.js, 18790)
  │   └─ Perception (Python, 8002)
  │
  └─ Layer 3: 后台任务（Layer 2 就绪后启动，可延迟）
      ├─ Weather Fetcher (Python daemon)
      ├─ RSS Fetcher (Node.js, 8003)
      └─ Web Watcher (Node.js)
```

### 为什么这样分层

| 层级 | 服务 | 为什么这样分 |
|------|------|-------------|
| Layer 0 | PG + Redis | 所有服务的依赖，必须最先就绪 |
| Layer 1 | API Gateway | 前端页面依赖它，必须在 UI 显示前就绪 |
| Layer 2 | LLM/Bridge/Perception | 核心功能，但前端可以先加载再连接 |
| Layer 3 | Weather/RSS/Web | 后台任务，不影响用户体验，可延迟启动 |

### 性能预估

| 指标 | Tauri 方案 | Electron 方案（对比） |
|------|-----------|---------------------|
| 安装包大小 | ~80MB | ~200MB |
| 内存占用 | ~300MB (全部服务) | ~500MB+ |
| 冷启动时间 | ~8s | ~12s |
| 热启动时间 | ~3s | ~5s |
| 渲染引擎内存 | ~50MB (系统 webview) | ~150MB (Chromium) |

## Tauri 深度集成设计

### Tauri 插件生态

| 插件 | 用途 | 替代 |
|------|------|------|
| `tauri-plugin-shell` | 子进程管理（sidecar） | `std::process::Command` |
| `tauri-plugin-updater` | 自动更新 | `electron-updater` |
| `tauri-plugin-store` | 持久化配置 | `electron-store` |
| `tauri-plugin-dialog` | 原生对话框 | `electron dialog` |
| `tauri-plugin-notification` | 系统通知 | 自行实现 |
| `tauri-plugin-log` | 日志收集 | `console.log` |

### Tauri Sidecar 机制

Tauri 的 sidecar 功能允许将外部二进制打包为应用的一部分，由 Rust 主进程管理：

```json
// tauri.conf.json
{
  "bundle": {
    "externalBin": [
      "vendor/python/{target-triple}/python3.12",
      "vendor/node/{target-triple}/node",
      "vendor/postgres/{target-triple}/postgres",
      "vendor/redis/{target-triple}/redis-server"
    ]
  }
}
```

Tauri 会自动：
- 根据目标平台选择正确的二进制
- 处理 PATH 和权限
- 提供 `tauri_plugin_shell::Command` API 来启动/停止

### Rust 进程管理核心逻辑

```rust
// 使用 tauri-plugin-shell 管理 sidecar
use tauri_plugin_shell::ShellExt;

// 启动 PostgreSQL sidecar
let sidecar_command = app.shell().sidecar("postgres").unwrap();
let (mut rx, mut child) = sidecar_command
    .args(["-D", &pgdata_dir, "-p", "5432"])
    .spawn()
    .expect("Failed to spawn postgres sidecar");

// 监听输出
tokio::spawn(async move {
    while let Some(event) = rx.recv().await {
        match event {
            CommandEvent::Stdout(line) => println!("PG: {}", line),
            CommandEvent::Stderr(line) => eprintln!("PG err: {}", line),
            CommandEvent::Terminated(_) => println!("PG exited"),
        }
    }
});
```

```rust
            commands::get_service_status,
            commands::get_config,
            commands::set_config,
```

### process_manager.rs

```rust
use tauri::{AppHandle, Manager};
use tauri_plugin_shell::ShellExt;
use std::sync::Arc;
use tokio::sync::RwLock;
use std::time::Duration;

pub struct ProcessManager {
    app: AppHandle,
    status: Arc<RwLock<ServiceStatus>>,
}

impl ProcessManager {
    pub fn new(app: AppHandle, status: Arc<RwLock<ServiceStatus>>) -> Self {
        Self { app, status }
    }

    // 分层启动（对齐 start.py 逻辑）
    pub async fn start_all(&self) -> Result<(), Box<dyn std::error::Error>> {
        // Layer 0: 基础设施
        self.start_postgres().await?;
        self.start_redis().await?;
        
        // Layer 1: 核心服务
        self.run_migrations().await?;
        self.start_api_gateway().await?;
        
        // Layer 2: 智能服务（并行）
        let (llm, bridge, perception) = tokio::join!(
            self.start_llm_gateway(),
            self.start_agent_bridge(),
            self.start_perception(),
        );
        llm?;
        bridge?;
        perception?;
        
        // Layer 3: 后台任务（不阻塞）
        self.start_background_services();
        
        Ok(())
    }

    async fn start_postgres(&self) -> Result<(), Box<dyn std::error::Error>> {
        let sidecar_command = self.app.shell().sidecar("postgres")?;
        let (mut rx, child) = sidecar_command
            .args(["-D", &self.pgdata_dir(), "-p", "5432"])
            .spawn()?;
        
        // 等待 pg_isready 就绪
        tokio::time::sleep(Duration::from_secs(2)).await;
        
        // 更新状态
        let mut status = self.status.write().await;
        status.postgres = true;
        
        Ok(())
    }

    // ... 其他服务启动方法类似
}
```

### postgres.rs

```rust
use std::path::PathBuf;
use std::process::Command;

pub struct PostgresManager {
    data_dir: PathBuf,
    port: u16,
}

impl PostgresManager {
    pub fn new(data_dir: PathBuf, port: u16) -> Self {
        Self { data_dir, port }
    }

    pub fn init_db(&self) -> Result<(), String> {
        // 首次启动：initdb + 创建用户/数据库
        let output = Command::new("initdb")
            .args(["-D", self.data_dir.to_str().unwrap()])
            .output()
            .map_err(|e| format!("Failed to run initdb: {}", e))?;
        
        if !output.status.success() {
            return Err(String::from_utf8_lossy(&output.stderr).to_string());
        }
        
        Ok(())
    }

    pub fn is_ready(&self) -> bool {
        // 检查 pg_isready
        Command::new("pg_isready")
            .args(["-p", &self.port.to_string()])
            .output()
            .map(|o| o.status.success())
            .unwrap_or(false)
    }
}
```

```rust
use tauri::{AppHandle, Manager};
use tauri_plugin_store::StoreBuilder;
use std::sync::Arc;
use tokio::sync::RwLock;

pub struct ConfigManager {
    store: Arc<RwLock<tauri_plugin_store::Store>>,
}

impl ConfigManager {
    pub fn init(app: &AppHandle) -> Result<Self, String> {
        let store = StoreBuilder::new(app, "config.json".into())
            .build()
            .map_err(|e| format!("Failed to create store: {}", e))?;
        
        Ok(Self {
            store: Arc::new(RwLock::new(store)),
        })
    }

    pub async fn get(&self, key: &str) -> Option<String> {
        let store = self.store.read().await;
        store.get(key).and_then(|v| v.as_str().map(String::from))
    }

    pub async fn set(&self, key: &str, value: &str) -> Result<(), String> {
        let mut store = self.store.write().await;
        store.set(key.to_string(), value.to_string());
        store.save().map_err(|e| format!("Failed to save: {}", e))
    }
}
```

### 后端 API

#### 1. 搜索接口

```python
# GET /api/skills/marketplace/search
# Query params: q, category, source, page, limit
# Response: { skills: [...], total: int, page: int }

@router.get("/search")
async def search_skills(
    q: str,
    category: str | None = None,
    source: str | None = None,  # skillsmp, skillhub, github
    page: int = 1,
    limit: int = 20,
):
    # 并行查询多个源
    results = await asyncio.gather(
        search_skillsmp(q, category, page, limit),
        search_skillhub(q),
        search_github(q),
    )
    # 聚合、去重、翻译
```

### 安全检测

```python
# services/api-gateway/app/services/skill_scanner.py

DANGEROUS_PATTERNS = [
    r'import\s+os\s*\.\s*system',
    r'subprocess\.(call|run|Popen)\s*\(',
    r'eval\s*\(',
    r'exec\s*\(',
    r'__import__\s*\(',
    r'rm\s+-rf',
    r'curl\s+.*\|\s*(bash|sh)',
]

async def scan_skill(files: dict[str, str]) -> ScanResult:
    """扫描技能文件，检测恶意代码"""
    for filename, content in files.items():
        for pattern in DANGEROUS_PATTERNS:
            if re.search(pattern, content):
                return ScanResult(
                    safe=False,
                    reason=f"检测到危险模式: {pattern} in {filename}"
                )
    
    return ScanResult(safe=True)
```
