# Plan: 三平台安装包打包方案

## 目标

将 Studio Arona 打包为 macOS (DMG)、Windows (NSIS/MSI)、Linux (deb/AppImage) 原生安装包，用户双击即可安装使用。

## 用户选择

- 分发形式：原生安装包 (DMG / NSIS / deb)
- ML 模型：可选组件（基础包不含，设置页手动下载）
- 数据库：内嵌 PostgreSQL + Redis

---

## 架构设计

### 整体结构

```
StudioArona/
├── electron/                    # Electron 主进程
│   ├── main.ts                  # 主进程：启动后端、加载前端
│   ├── preload.ts               # 预加载脚本
│   ├── tray.ts                  # 系统托盘
│   ├── updater.ts               # 自动更新
│   └── backend/                 # 后端进程管理
│       ├── process-manager.ts   # 子进程生命周期
│       ├── postgres.ts          # 内嵌 PG 管理
│       ├── redis.ts             # 内嵌 Redis 管理
│       └── services.ts          # Python/Node 服务管理
├── apps/web/                    # 前端（已有）
├── services/                    # 后端服务（已有）
├── vendor/                      # 嵌入式运行时
│   ├── python/                  # 已有三平台 Python
│   ├── node/                    # 三平台 Node.js 二进制
│   ├── postgres/                # 三平台 PG 二进制
│   └── redis/                   # 三平台 Redis 二进制
├── scripts/
│   └── package.sh               # 打包脚本
└── electron-builder.yml         # electron-builder 配置
```

### 技术选型：Electron

**选择理由**：
- 成熟的跨平台打包方案（electron-builder / electron-forge）
- 原生菜单、托盘、自动更新支持
- 可嵌入任何后端（Python/Node）
- 社区生态完善，NSIS/DMG/deb 一键生成
- 前端已经是 React，天然适配

**替代方案对比**：

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| Electron | 生态好，打包成熟 | 包体大 (~150MB 基础) | ✅ 选择 |
| Tauri | 包体小 (~10MB) | Rust 学习成本，系统 webview 兼容性差 | ❌ |
| PyInstaller + NSIS | 原生 Python | Node.js 服务难打包，无 GUI 壳 | ❌ |
| Docker 镜像 | 一致性强 | 需要用户装 Docker，非原生体验 | ❌ |

## 三平台打包规格

### macOS (DMG)

| 项目 | 规格 |
|------|------|
| 格式 | DMG (拖拽安装) |
| 架构 | Universal Binary (arm64 + x64) |
| 基础包大小 | ~200MB (不含模型) |

**安装流程**：
1. 用户下载 `StudioArona-1.0.0.dmg`

3. 首次启动：自动初始化 PG/Redis/数据库
4. 系统托盘常驻，菜单栏显示状态

### Windows (NSIS)

| 项目 | 规格 |
|------|------|
| 格式 | NSIS 安装器 (.exe) |
| 架构 | x64 (ARM64 需交叉编译) |
| 基础包大小 | ~180MB (不含模型) |
| 最小系统 | Windows 10 1809+ |
| 签名 | Authenticode (需证书) |
| 自动更新 | electron-updater |
| 开机自启 | 可选 (安装时勾选) |

**安装流程**：
1. 用户运行 `StudioArona-Setup-1.0.0.exe`
2. 选择安装目录、开机自启
3. 安装完成自动启动
4. 系统托盘常驻

### Linux (deb + AppImage)

| 项目 | 规格 |
|------|------|
| 格式 | deb (Ubuntu/Debian) + AppImage (通用) |
| 架构 | x64 |
| 基础包大小 | ~170MB (不含模型) |
| 最小系统 | Ubuntu 20.04+ / Fedora 35+ |
| 自动更新 | electron-updater |

**安装流程**：
1. `sudo dpkg -i studio-arona_1.0.0_amd64.deb`
2. 或 `chmod +x StudioArona-1.0.0.AppImage && ./StudioArona-1.0.0.AppImage`

## 内嵌服务设计

### PostgreSQL

- **二进制来源**：[postgresql-portable](https://github.com/nickoala/pgportable) 或自行编译静态链接版本
- **macOS**：PostgreSQL.app 二进制 (~30MB)
- **Windows**：EDB 官方 zip 包 (~30MB)
- **Linux**：静态编译 pg (~25MB)
- **数据目录**：`~/Library/Application Support/StudioArona/pgdata` (macOS) / `%APPDATA%/StudioArona/pgdata` (Windows) / `~/.config/studio-arona/pgdata` (Linux)
- **端口**：5432 (默认，可配置)
- **启动**：Electron 主进程在启动时 fork PG 进程，等待 `pg_isready` 就绪

### Redis

- **二进制来源**：官方预编译二进制 (~5MB)
- **数据目录**：同 PG 数据目录下的 `redis/`
- **端口**：6379 (默认，可配置)
- **启动**：Electron 主进程 fork Redis 进程

### Python 后端

- **运行时**：已有 `vendor/python/<plat>/` (25-44MB)
- **依赖**：通过 `uv sync` 安装到应用目录
- **服务**：API Gateway + LLM Gateway + Perception
- **启动**：Electron 主进程 fork Python 进程

### Node.js 后端

- **运行时**：嵌入 Node.js 二进制 (~40MB)
- **依赖**：`node_modules` 打包进应用
- **服务**：Agent Bridge + RSS Fetcher + Web Watcher
- **启动**：Electron 主进程 fork Node 进程

## Electron 主进程设计

### 核心流程

```
App Launch
  ├─ 1. 检查/初始化数据目录
  ├─ 2. 启动 PostgreSQL (fork, 等待 pg_isready)
  ├─ 3. 启动 Redis (fork, 等待 redis-cli ping)
  ├─ 4. 运行 alembic upgrade head
  ├─ 5. 启动 Python 服务 (API Gateway + LLM Gateway + Perception)
  ├─ 6. 启动 Node.js 服务 (Agent Bridge + RSS + Web Watcher)
  ├─ 7. 构建前端 (或加载预构建的 dist/)
  ├─ 8. 打开 BrowserWindow 加载前端
  ├─ 9. 注册系统托盘
  └─ 10. 监听子进程，自动重启
```

### 进程管理

```typescript
class ProcessManager {
  // 启动顺序保证
  async startAll() {
    await this.startPostgres();    // 必须最先
    await this.startRedis();       // 其次
    await this.runMigrations();    // PG 就绪后
    await this.startPythonServices();  // 可并行
    await this.startNodeServices();    // 可并行
  }
  
  // 健康检查 + 自动重启
  // 子进程崩溃时自动重启（最多 3 次）
  // 全部崩溃时提示用户
}
```

## 打包脚本

### `scripts/package.sh`

```bash
#!/bin/bash
# 一键打包三平台安装包

PLATFORM=$(uname -s | tr '[:upper:]' '[:lower:]')

# 1. 构建前端
cd apps/web && pnpm build && cd ../..

# 2. 安装 Python 依赖到 vendor
uv sync --all-packages

# 3. 安装 Node.js 依赖
cd services/agent && pnpm install --prod && cd ../..

# 4. 下载平台特定的 PG/Redis/Node 二进制
./scripts/download-vendor.sh $PLATFORM

# 5. 打包
npx electron-builder --${PLATFORM}
```

### GitHub Actions CI

```yaml
# .github/workflows/release.yml
name: Release
on:
  push:
    tags: ['v*']

jobs:
  build:
    strategy:
      matrix:
        os: [macos-latest, windows-latest, ubuntu-latest]
    runs-on: ${{ matrix.os }}
    steps:
      - uses: actions/checkout@v4
      - run: ./scripts/package.sh
      - uses: softprops/action-gh-release@v2
        with:
          files: dist/*
```

## 实施步骤

### Phase 1: 基础框架 (3-5天)

1. **初始化 Electron 项目**
   - `electron/` 目录结构
   - `main.ts` 基础窗口
   - `electron-builder.yml` 配置
   - 前端 build 集成

2. **进程管理器**
   - `ProcessManager` 类
   - 子进程 fork/restart 逻辑
   - 健康检查

3. **内嵌 PG/Redis**
   - 下载脚本 (`scripts/download-vendor.sh`)
   - PG/Redis 启动封装
   - 数据目录管理

### Phase 2: 服务集成 (3-5天)

4. **Python 服务管理**
   - API Gateway 启动
   - LLM Gateway 启动
   - Perception 启动
   - 日志收集

5. **Node.js 服务管理**
   - Agent Bridge 启动
   - RSS/Web Watcher 启动
   - 端口分配

6. **数据库迁移**
   - alembic 集成
   - 首次启动自动迁移

### Phase 3: 原生体验 (3-5天)

7. **系统托盘**
   - 托盘图标 + 菜单
   - 服务状态显示
   - 开机自启

8. **自动更新**
   - electron-updater 集成
   - GitHub Releases 发布
   - 更新检查 + 下载

9. **安装器定制**
   - macOS: DMG 背景图 + 拖拽指引
   - Windows: NSIS 界面定制 + 安装选项
   - Linux: desktop 文件 + 图标

### Phase 4: 模型管理 (2-3天)

10. **模型下载器**
    - 设置页 UI
    - modelscope 集成
    - 断点续传
    - 进度显示
