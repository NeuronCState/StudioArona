# 系统架构与关键技术选型

整个系统可分为硬件平台、虚拟化环境、AI Agent、前端交互、外设接口等几个部分。硬件上采用一台 **Ubuntu 虚拟机**（16GB V100 GPU、双路 Xeon E5-2650 v2 CPU、32GB 内存），挂载屏幕、单目摄像头和基于 STM32 的舵机机械臂。虚拟化方面可在 Ubuntu 上用 VirtualBox 部署两台子虚拟机：一台作为 NAS（网络存储），一台跑 HomeAssistant。网络连接通过交换机实现，Agent 有局域网管理权限。

**AI Agent 框架**：当前主流的开源 Agent 框架包括 *Hermes Agent* 和 *OpenClaw* 等。Hermes 强调“自我演化”与跨会话记忆，具备技能文档自动沉淀机制【18†L0-L4】；OpenClaw 则是一个“网关驱动”的助手平台，技能系统成熟，可通过 Markdown 文件定义**技能（Skill）**【32†L148-L156】。考虑到需要长期运行和多样化任务，两者都可研究并评估。Hermes 以同步对话循环为核心，能够跨会话检索记忆和持续优化技能【12†L829-L839】【18†L0-L4】；OpenClaw 拥有庞大的社区技能生态（ClawHub 上数千技能可用【32†L148-L156】），更侧重于多渠道会话和工具调用。最终可根据需求选择，或让两者协同——例如用 Hermes 作为核心运行时，利用 OpenClaw 技能库丰富能力。

**LLM 模型与推理优化**：为保证低延迟和高质量，可考虑**本地部署开源模型**，减少网络延迟。2026 年的先进开源模型层出不穷，如 *DeepSeek-V4*、*MiMo-V2.5-Pro*、*Gemma 4*、*GLM-5.1*、*Qwen3.5* 等【25†L129-L137】【39†L323-L331】【39†L373-L381】【39†L419-L425】。例如，DeepSeek-V4 支持百万级上下文长度【25†L129-L137】，MiMo-V2.5 专注编程和多模态场景【25†L233-L240】，GLM-5.1（智谱）在编程基准上领先开源阵营【39†L323-L331】，Qwen3.5（阿里）原生支持 262K 令牌窗口，可扩展至百万级【39†L373-L381】，Gemma4（谷歌开放权重）31B 模型在单卡（80GB）上已展现顶级推理能力【39†L419-L425】。根据硬件算力（V100 16GB），可选择量化或剪枝的中小规模版本（如 Qwen3.5 的 35B-A3B 或 30B 版本、MiMo-V2.5 15B、LLama4 8B/13B 等），并结合推理优化工具（如 [vLLM](https://github.com/vllm-project/vllm) 和 [Ollama](https://www.ollama.com/)）减少延迟。事实证明，本地推理可提供“秒级”响应、无需网络往返【30†L83-L91】。同时也可预留接口调用云端模型（如 OpenAI GPT-4o 或阿里云智言等），兼顾效果与时效，但需考虑境内网络限制。

**前端与交互技术**：建议前端使用现代前端框架（如 React、Vue3）结合 Vite 构建【17†L95-L101】【16†L83-L91】。Vite 作为“下一代前端构建工具”，提供极速热更新和模块化开发体验【17†L95-L101】；实践中已有开发者用 Vite+React 实现低延迟实时聊天应用【16†L83-L91】。聊天界面采用长链接推送（如 **Server-Sent Events** 或 WebSocket）逐步渲染模型回复，以降低延迟并增强交互感。比如 SSE 可让服务器在单个持久连接上推送 AI 输出流，适用于聊天和实时生成【34†L116-L124】【34†L169-L177】。在唤醒后转竖屏显示特定页面、跟踪人脸和语音对话时，可通过前端监听触发事件、动态调整 CSS/布局。

**外设与其他系统**：摄像头和 STM32 云台部分可参考已有方案——PC（Ubuntu）端使用 OpenCV 等库做实时人脸检测，再通过串口把人脸坐标发给 STM32，STM32 用 PID 算法驱动舵机【37†L60-L68】【37†L88-L93】。这个双端架构简单可靠：PC 端采集视频→OpenCV 检测人脸→串口传坐标→STM32 控制旋转云台【37†L60-L68】。NAS 可通过 Samba/NFS 挂载或 Docker 容器实现，并开放文件查询接口；HomeAssistant 可开放其 REST API 供 Agent 调用；局域网设备监控可使用 SNMP、ARP 扫描或现成的网管协议。总之，**技术选型**上推荐使用开源、成熟且**中国可访问**的工具（如国内开源 LLM、Vite、OpenCV、STM32生态等），保证系统稳定可靠。

# 各模块设计与实现方案

1. **唤醒与用户识别**：通过麦克风实时监听唤醒词或按钮触发事件。触发后使用摄像头进行人脸识别（可以用人脸检测 + 识别模型，如 OpenCV+DNN，或国内人脸识别库），判断唤醒者身份。代理会话时加上用户身份作为上下文前缀。用户信息（身份、偏好）可保存在本地数据库（如 SQLite）中，作为对话上下文的一部分【18†L0-L4】。

2. **屏幕旋转与状态切换**：根据检测结果控制舵机旋转显示屏。前端收到唤醒命令后，可以调用一个后端接口执行屏幕纵置（操作 Linux 显示方向）并启动人脸跟踪服务。人脸跟踪部分如上文所述，可借鉴【37†L60-L68】所示方案。屏幕竖置后加载特定对话页面（如全屏）并启动实时对话。退出时则重置为横屏并清空会话。

3. **对话界面与实时渲染**：前端页面通过 SSE 或 WebSocket 连接后台 Python/Node 服务器，后台以流水线模式调用 LLM 生成回复。可以结合 LangChain 等库实现“分块流式输出”【34†L169-L177】。例如，使用 FastAPI + SSE 的方式：客户端发送用户消息，服务器启动 LLM 流式推理，每产生一段内容就以 `data: ...\n\n` 推送给前端【34†L116-L124】【34†L169-L177】。这样用户看到实时打字效果。Vue/React 页面监听 `EventSource` 事件，更新对话框内容。若用 OpenClaw/Hermes 运行 Agent，可在 Gateway 层捕获输出，同样流式转发。

4. **Agent 核心与技能系统**：后端选用 Hermes 或 OpenClaw 运行 Agent 核心。通过**技能（Skill）**机制封装各子任务。例如：查询 NAS 空间、配置 RSS、管理虚拟机、记录日程等，都实现为独立技能。OpenClaw 技能定义为带前置 YAML 的 Markdown 文件【32†L148-L156】，安装后 Agent 可自动识别并调用；Hermes 则可通过其内置记忆和技能文档机制【18†L0-L4】持续优化任务执行。技能之间通过 Agent 消息上下文共享信息，各技能对外依赖（如 NAS API、虚拟机控制命令 VBoxManage、RSS 源解析库等）可作为工具注册到 Agent 中。

5. **知识库与记忆**：使用 Agent 框架的持久化功能（如 Hermes 的 FTS5 全文搜索【1†L67-L75】）存储对话历史与用户偏好。每次唤醒时，Agent 从记忆库召回用户历史对话和偏好。这可保证对话连贯，并将个性化信息（如常用任务、喜好设置等）注入系统提示。需要定期清理过时信息，或在用户离开时重置短期上下文。

6. **外部数据源管理**：对于用户需求如“NAS 最近存了哪些东西”“配置 RSS 源”等，Agent 可借助技能访问对应接口。比如配置 RSS 时，Agent 将页面展示给用户确认【32†L148-L156】；用户确认后，Agent 在后端使用 RSS 库抓取源头数据，并在订阅页面记录设置。RSS 更新触发时，Agent 可自动下载新内容、生成摘要（调用 LLM 进行摘要生成，结果用 Markdown 格式化），并推送提醒。类似地，日程规划可使用本地数据库或日历服务，Agent 接收自然语言命令后创建日程项、设置倒计时触发器等。

7. **网络与系统监控**：Agent 还需负责网络内设备监控。可利用 Python 库进行局域网扫描（例如使用 `python-nmap`、`scapy` 等）或 SNMP 协议读取交换机上运行情况。若交换机支持 SNMP，可通过 SNMP 客户端获取各端口流量、设备列表。对于虚拟机（VirtualBox），Agent 可调用 `VBoxManage` 等命令行工具查询 VM 状态、资源使用情况，并通过技能向用户报告。这样，在对话中用户询问“Ubuntu 负载如何”“某 VM 状态”等时，Agent 可实时查询并回复。

8. **语音交互（选项）**：若需要语音输入输出，可集成中文语音识别和合成。国内可用的方案包括讯飞/百度离线包、开源 DeepSpeech/Coqui TTS 等。例如用 Whisper 类似模型做语音转文本，再交给 Agent 处理；回复后用本地 TTS 引擎合成语音并通过扬声器播放。OpenClaw 也提供 [TTS 工具](https://cloud.tencent.com/developer/tag/语音合成)，可以作为参考【4†L118-L126】。

# 实现难点与安全考虑

1. **低延迟对话**：模型推理本身可能耗时，对话需要实时响应。可通过流式输出减小感知延迟【34†L116-L124】。同时，可利用模型的“推理模式”调整质量和速度（如 DeepSeek-V4 的非思考/思考模式【25†L168-L177】）。还可并行处理：前端与 Agent 通信走异步通道（SSE/WebSocket），Agent 在后台同步循环调用 LLM【12†L829-L839】，不会阻塞 UI。

2. **并发与资源管理**：多用户或多任务同时发起时需要调度。Hermes 提供子 Agent 并行机制和独立预算【12†L829-L839】；可设定并行线程池处理非交互任务（如长期抓取 RSS），尽量避免主会话堵塞。注意 GPU 内存分配：尽量不要同时加载多个大型模型，多模态和大上下文推理可限流或用较小模型替代。

3. **数据安全**：由于 Agent 在内网且权限较高，安全风险不容忽视。一方面要限制技能的可信度：Hermes 设计中支持“可用性检查”动态降级缺乏 API Key 的工具【1†L119-L128】；OpenClaw 社区发现（如 [CVE-2026-25253](https://nvd.nist.gov/vuln/detail/CVE-2026-25253)）技能文件有被注入恶意指令的风险【32†L195-L203】。因此务必控制技能来源，只使用经过审核的技能，避免自动执行不明脚本。网络层面，Agent 不应随意发包或跳板到其他子网，访问权限限定在工作室内部设备。所有外部接口（如 NAS、HomeAssistant API）应使用认证。

4. **网络权限边界**：Agent 需要访问交换机和局域网设备，可能需要 SNMP 读权限或网络扫描权限。部署时需在交换机上开启适当的只读社区或 SNMPv3 账号，并在 Ubuntu 上配置。务必与网络管理员协商，确保该操作符合公司安全策略。对于业务应用（如公司外网服务），Agent 不应具备访问权。

5. **集成复杂性**：各模块需标准化接口。如前端与后端通信采用统一 JSON 格式协议；Agent 技能通过 API 或 CLI 工具调用，本地可用性检测并记录日志【1†L119-L128】【32†L169-L178】。面对连接 N 个子系统（面部识别、语音识别、虚拟机管理等），需设计清晰的调用链，保证单个模块失败时能够优雅降级。例如无人唤醒时 Agent 定期休眠，摄像头闲置；出现 OCR 或 TTS 错误时给用户提示，不影响其他服务。

# 分阶段实施计划

1. **环境搭建（0.5-1 个月）**：配置 Ubuntu 虚拟机、安装必备环境。搭建 VirtualBox 并创建 NAS、HomeAssistant VM，确保网络互通和资源共享。前端使用 Vite 创建基础聊天页面骨架并部署。实现基本的人脸检测例子（OpenCV Haar 或 DNN）和 STM32 串口通信测试，验证机械臂/屏幕旋转功能。

2. **Agent 原型与对话流（1-2 个月）**：选择 Agent 框架（先用较成熟的一个，后续可扩展）。实现一个简单循环：前端发消息 → Agent 调用 LLM 输出 → 前端显示。可先用小模型或 OpenAI API 做功能验证。搭建 SSE 通道进行流式响应【34†L116-L124】【34†L169-L177】。同时让 Agent 完成第一个技能：如“查询 NAS 文件”或“上网搜索”并返回结果。此阶段完成系统端到端互动原型。

3. **扩展技能与系统集成（2-3 个月）**：依次开发各项技能模块，例如 NAS 状态查询、RSS 配置与推送、日程管理、虚拟机管理、网络设备监控等。每个技能通过 CLI 或 API 调用实现：如执行 `VBoxManage` 管理 VM、使用 `feedparser` 解析 RSS、调用系统命令统计磁盘使用等。Agent 使用记忆库记录多轮对话信息和用户偏好，实现响应更自然。此阶段着重模块功能完整和稳定测试。前端增加相应页面（如 RSS 源列表、日程列表、网络设备概览），并与 Agent 对话内容绑定。

4. **优化与测试（1-2 个月）**：优化性能和用户体验。针对推理延迟做并发/异步优化或模型更换。安全审计技能代码，禁止高危操作。整理自动化测试脚本，模拟用户唤醒、连续问答、并行任务等场景，修复 bug。部署前进行压力测试，确保 GPU/CPU 利用率在可控范围。完成文档编写，培训用户如何使用唤醒指令和看板功能。

5. **上线与迭代**：系统上线运行后持续监测日志和性能。收集反馈，逐步扩充技能（可编写新 OpenClaw 技能发布到私有仓库，或更新 Hermes 技能文档）。定期升级模型库（按需要更新至更优性能的模型），更新基础软件（TensorRT、CUDA、库版本）以维持安全与效率。

# 运维与扩展建议

- **监控与日志**：实时监控GPU/CPU负载、内存使用。记录Agent对话日志和系统日志，以便排查异常。可以为Agent服务配置日志轮替和错误告警。  
- **硬件扩展**：如需支持更多并发或更大模型，可考虑增添GPU或升级至更强服务器。部分耗时任务可分流到边缘设备（如离线语音识别可在树莓派上执行）以减轻主机负担。  
- **持续集成**：建立CI/CD流程，自动化部署前端与后端代码更新。对于Agent技能更新，可在测试环境验证后再发布到线上。  
- **权限管理**：定期审查Agent所用的系统账号权限，最小化授权。对于新增功能（如接入新API），需评估安全风险。  
- **备份与恢复**：定期备份对话记忆库和用户数据，以防故障。对虚拟机（NAS/HA）亦需制定快照和备份策略。  
- **性能评估**：定期评估聊天机器人响应时长和准确率，对重要技能进行回归测试。适时替换或微调模型，平衡延迟与质量。如可使用如 BentoML 这类工具监控模型服务性能【29†L18-L22】。  
- **资源估算**：初期开发投入约 3-6 个月，由 1-2 人团队完成。后续维护需设置专人监控运行状态。硬件成本主要是现有资源，可视需求追加 GPU 或存储。模型运行时的电力和冷却也需考虑在内。

通过上述方案，可建立一个功能全面、响应迅速的智能公告板系统。各模块选用当前领先的技术：前端用 Vite 【17†L95-L101】和 SSE 实现流式聊天界面 【34†L116-L124】；Agent 采用开放框架（Hermes/OpenClaw）加多技能架构【32†L148-L156】【18†L0-L4】；对话模型引入最新开源成果（DeepSeek、Qwen、Gemma 等）【25†L129-L137】【39†L323-L331】。整体设计注重模块化、可维护性和安全，符合国内部署环境和操作规范，可逐步迭代升级，实现类似“工作室贾维斯”的智能公告板目标。
