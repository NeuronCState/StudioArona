## 1. 我的目标（一句话）

把工作室贾维斯做成一个**像 Claude 桌面端那样克制、干净、有"呼吸感"**的网页：左侧导航栏 5 个页面，对话页能像 ChatGPT 实时语音那样进入/退出，Agent 能自己切页/插组件。

## 2. 我的边界

- `packages/ui-kit/`：可独立开发的 Claude Design 组件库 + Storybook

## 3. 协作锚点（与 00 文档一致）

- **HTTP 接口**：从 `packages/contracts/openapi.yaml` 自动生成 TS 类型，import `@javis/contracts`。
- **SSE 协议**：见 00 §3.2。我维护 `apps/web/src/lib/sse-client.ts`，向 B 暴露 hook `useChatStream(sessionId)`。
- **WS 事件**：见 00 §3.3。我维护 `apps/web/src/lib/event-bus.ts`，暴露 `useWakeEvents()`。
- **Mock**：B/C 没好之前，所有接口走 `MSW`（Mock Service Worker），假数据放 `apps/web/src/mocks/`。
- **B 的 `ui_action` 事件** 是 Agent 操作前端的入口，我维护 dispatcher：

```ts
// apps/web/src/lib/ui-actions.ts
// 与 packages/contracts/ui-actions.schema.json 同步
type UIAction =
  | { type: 'navigate'; to: string }
  | { type: 'highlight'; selector: string }
  | { type: 'render_card'; payload: Card }
  | { type: 'clear_session' }
  | { type: 'toast'; message: string; level: 'info'|'warn'|'error' }
  | { type: 'confirm'; message: string; action: string }
```

任何新动作 → 三方（A/B 必参与）讨论后加入这里，并写到 OpenAPI 注释。

## 4. 五个页面（产品形态）

### 4.1 整体壳

- 左侧 64px 窄导航（5 个图标 + 头像 + 设置），Claude Design 风格：极淡边框、`text-zinc-700` 主色、强调色 `#D97757`（暖橙）。
- 顶栏极简，仅显示当前页面标题 + 在线状态点（灰=未唤醒 / 橙=对话中 / 蓝=后台任务运行）。
- 全站字体：`Inter` + `Noto Sans SC`，等宽用 `JetBrains Mono`。
- 暗黑模式跟随系统。

### 4.2 页面 1：对话（默认页 `/`）

**默认形态**：横屏时显示工作室"今日概览"卡片群 —— 共享日程、最近 RSS 摘要、Ubuntu 状态徽章。这是"公告板模式"。

**唤醒形态**：收到 `wake` 事件后：
1. 整页做一次 1.2s 的 CSS rotate(90deg) + scale 转场动画（视觉模拟"屏幕旋转"，与 C 的真实硬件解耦）；
2. 切到全屏对话布局（中间气泡，底部输入框 + 麦克风图标）；
3. 不自动开口（默认文字模式），但底部出现"按住说话"按钮；
4. 摄像头跟脸数据 (`face_track` 事件) 在右下角小窗显示（小圆形画面 + 脸框叠加），可关闭。

**离开形态**：`leave` 事件后：
1. 倒计时 5s "无人，即将清空"提示（可点击保留）；
2. 倒计时结束 → 反向 rotate 动画 → 回到公告板模式 + 清空当前会话 UI（数据由 B 在后端处理）。

**注册用户登录进来**：直接进对话形态，不走唤醒动画，不自动开语音。

**实时渲染**：Markdown + 代码块 + 引用块 + 工具调用气泡（"正在查询 NAS…"）+ Agent 主动插入的 Card（来自 `ui_action: render_card`）。

**关键交互细节**：
- 流式输出做"光标闪烁"+ "字符渐入"，避免突兀。
- 用户停止说话 / 输入 200ms 后才发送，避免抖动。
- 长回答 > 3 屏自动出现"回到底部"浮钮。

### 4.3 页面 2：我的信息源（`/me/feeds`）

- **订阅栏**：卡片网格，每个 RSS 一卡（封面 + 标题 + 上次更新时间 + AI 摘要预览 + 是否提醒铃铛）。
- **日程栏**：时间轴，倒计时大数字（24h 内的事项突出橙色），点击展开详情。
- **添加 RSS**：右上 + 按钮 → 弹窗，但鼓励用户用对话页说"帮我加 xxx" —— 弹窗里也显示"你可以直接对 Javis 说"。
- **摘要详情页**：进入某条 RSS item → AI 生成的 markdown 摘要 + "原文" 跳转链接。

### 4.4 页面 3：共享信息源（`/shared`）

- 与页面 2 布局相同，但数据 scope=shared。
- 编辑权限矩阵显式可见：哪些卡片"全员可改"、哪些"只创建者可改"，由用户角色 + scope 决定。
- 顶部加一个"工作室公告"区，置顶事项。

### 4.5 页面 4：虚拟机申请（`/vms`）

**列表**：每人一卡片（最多 1 台 VM），状态徽章（running / stopped / creating）。

**新建表单**：
- CPU 核数（slider，1–8，余量来自 `system/metrics`）
- 内存（slider，2–16 GB）
- 硬盘（input，10–200 GB）
- 镜像（select：ubuntu-22.04 / cuda-12.x，Mac 阶段两个都假）
- 备注（text）
- 提交 → "排队中" → "创建中" → "可用"（轮询 `/api/vms/:id`）

**详情卡**：
- Web SSH 嵌入（`ttyd` iframe，Mac 阶段嵌入一个假终端 mock，按下回车有打字机动画响应）
- 上传压缩包（拖拽区，进度条，Mac 阶段 mock 上传到本地临时目录）
- 销毁按钮（二次确认）

### 4.6 页面 5：Ubuntu 硬件（`/system`）

- **GPU 卡组件**：型号 / 显存 / 温度 / 利用率，环形进度。Mac 阶段显示固定 V100 + 假数据。
- **CPU 网格**：每核一格小柱状图（双路 16 核 = 32 格），实时滚动。
- **内存 / 磁盘**：横向条。
- **当前训练任务**：表格（用户 / 任务名 / 已运行 / 剩余预估 / 当前 step）。
- **网络设备**：表格（IP / MAC / 厂商 / 是否在线 / 最近活跃），来自 C 的 `network/devices` 接口。

刷新策略：WS 推送（`metrics_update` 事件，由 D 中转 C 的数据）+ 用户手动刷新。

## 7. 开发规范

### 7.1 代码风格
- ESLint：`@typescript-eslint/strict` + `react/recommended` + 自定义 `no-default-export`（除 page route 外）。
- Prettier：宽 100，单引号，trailing comma all。
- 组件命名：PascalCase 文件 + 同名导出；hook 用 `useXxx`。
- 一个文件 ≤ 300 行；超出强制拆。

### 7.2 目录约定（apps/web/src）

```
src/
├── pages/             # 路由页面，按 5 个页面分目录
├── features/          # 业务模块（chat / feeds / schedule / vm / system）
├── components/        # 跨页面共用展示组件
├── lib/               # sse-client / event-bus / ui-actions / api / auth
├── hooks/
├── stores/            # zustand
├── mocks/             # MSW handlers
├── styles/
└── types/
```

### 7.3 状态原则
- **服务端状态走 TanStack Query**，不要塞进 zustand。
- **跨页 UI 状态走 zustand**（导航栏、唤醒态、当前会话 id）。
- **组件本地状态用 useState**。
- 不搞 Redux，不搞 Context 滥用。

### 7.4 接口调用
- 全部经 `src/lib/api/` 的 typed client（基于 OpenAPI 自动生成）。
- 不允许在组件里直接 fetch。
- 所有调用必须有 loading / error 处理。

### 7.5 可访问性
- 全键盘可达；焦点环不要被 `outline:none` 干掉。
- 颜色对比 ≥ WCAG AA。
- 图片 / 图标必须有 aria-label。
- 流式内容用 `aria-live="polite"`。

## 8. 测试规范

### 8.1 测试金字塔（前端段）

```
        ┌────────────────────────┐
        │  Playwright E2E (慢)   │  关键旅程
        ├────────────────────────┤
        │ 视觉回归 (snapshot)    │  Storybook + Playwright screenshots
        ├────────────────────────┤
        │ 集成 (Vitest + MSW)    │  features/* 组件 + 假后端
        ├────────────────────────┤
        │ 单元 (Vitest + RTL)    │  hooks / lib / utils
        └────────────────────────┘
```

### 8.2 单元测试
- 工具：**Vitest** + **@testing-library/react**。
- 范围：所有 `lib/`、`hooks/`、纯展示组件。
- 命名：`*.test.ts` / `*.test.tsx`，与源码同目录。
- 覆盖率门槛：`lib/` ≥ 90%，整体 ≥ 75%。

```bash
pnpm --filter web test           # 全跑
pnpm --filter web test --watch
pnpm --filter web test --coverage
```

### 8.3 集成测试
- **MSW** 起假后端，覆盖所有 API（用 `mocks/handlers.ts`）。
- 每个 feature 至少一条"happy path"和一条"error path"。
- 流式 SSE 测试：用 MSW 的 ReadableStream mock 验证渐进渲染。

### 8.4 E2E（Playwright）

**必须覆盖的 5 条旅程**：

1. **登录 → 5 页面 smoke**：能点开每一页且不报错。
2. **唤醒对话流**：点"假装唤醒" → 旋屏 → 发送一条消息 → 收到流式回复 → 倒计时清空。
3. **RSS 添加 → AI 摘要**：从对话页让 Agent 加 RSS → 切到信息源页验证存在 → 点详情看摘要。
4. **日程对话流**：对话说"明天 10 点开会" → 切到日程页看到条目 + 倒计时。
5. **VM 申请**：填表 → 提交 → 状态轮询变化 → 终端 mock 响应 → 销毁。

```bash
pnpm --filter web e2e            # headless
pnpm --filter web e2e --ui       # 可视
```

E2E 跑在 CI nightly + 本地按需。**关键 PR 必跑前 2 条**。

### 8.5 视觉回归
- Storybook stories 覆盖所有 ui-kit 组件 + 5 个页面的关键状态。
- Playwright `toHaveScreenshot()` 比对，差异阈值 0.2%。
- 视觉 diff 在 PR 评论里贴图。

### 8.6 性能与可访问性
- Lighthouse CI：每 PR 跑，LCP < 2s / CLS < 0.1 / TBT < 300ms 卡线。
- axe-core 集成进 Playwright，0 critical。

### 8.7 Mock 数据维护
- `mocks/data/*.ts` 是有意义的工作室真实场景数据（成员名字、真实 RSS 链接形态等）。
- 数据漂移检测：每周一 D 跑契约测试，发现 mock 与真实 schema 不一致即报警。
