## 5. API Gateway 详细

### 5.1 职责
- 端口 8080（开发） / 443（生产 + Nginx 反代）
- 鉴权：登录、刷新、`Authorization: Bearer` 校验
- 限流：基于 Redis 的 token bucket（匿名 / 已登录两档）
- SSE 中转：浏览器连 gateway → gateway 连 agent；保持心跳
- WS 中转：浏览器连 `/ws/events` → gateway hub → 接收 perception 推送
- 内部 API：`/internal/*` 仅监听 unix socket 或 127.0.0.1，跨服务调用
- 统一错误格式：

```json
{ "code": "JAVIS_AUTH_EXPIRED", "message": "请重新登录", "trace_id": "..." }
```

### 5.2 鉴权细节
- 密码：bcrypt cost=12。注册仅支持管理员添加（工作室是封闭社群）。
- JWT：HS256（dev）/ RS256（prod），TTL 1h，refresh token 7d。
- 注销：refresh token 入 Redis 黑名单。
- 角色：`admin` / `member`。共享区编辑、用户管理仅 admin。

### 5.3 SSE/WS 中转关键点
- SSE：`stream=True` 直透 agent 的 `text/event-stream`，每 15s 注入 `: keepalive\n\n` 心跳。
- WS：用 `websockets` 库的 hub 模式，按 user_id fan-out。
- 断线自动清理订阅，避免泄漏。

## 6. 数据库 schema 与迁移

### 6.1 Alembic 工作流
- 任何 schema 改动 → 在 `infra/db/migrations/` 加一条迁移（基于 `services/*/models.py` 的 SQLAlchemy 元数据 autogenerate）。
- 迁移命名：`{ts}_{slug}.py`，包含 upgrade + downgrade。
- 启动顺序：app 启动时跑 `alembic upgrade head`。
- 数据迁移分两步：先加列（兼容），后删旧列；不允许一步破坏性改动。

### 6.2 核心表（与 00 §3.5 一致，这里给出权威 SQLAlchemy 模型存放位置）

| 表 | owner（写入侧） | 模型位置 |
|---|---|---|
| users / user_preferences / user_face_embeddings | D | `services/api-gateway/app/models/user.py` |
| chat_sessions / chat_messages / agent_memories | B | `services/agent/app/models/chat.py` |
| feeds / feed_items / schedules | B | `services/agent/app/models/feeds.py` |
| system_metrics_snapshot / vm_records | C | `services/perception/app/models/system.py` |
| audit_log | D | `services/api-gateway/app/models/audit.py` |

跨服务**通过 ORM 共用同一个 PG 数据库**；schema 元信息全部聚合到 `infra/db/metadata.py` 用于 alembic 扫描。

### 6.3 备份
- pg_dump 每日 03:00（cron），保留 7 天本地 + 30 天远端（Linux 阶段挂 NAS）。
- Redis 不备份（只放会话/缓存）。

## 8. Docker Compose（本地开发）

### 8.1 一键起（Mac 上）

```yaml
# infra/compose/docker-compose.yml
services:
  postgres:
    image: postgres:16
    environment:
      POSTGRES_USER: javis
      POSTGRES_PASSWORD: javis
      POSTGRES_DB: javis
    volumes: [pgdata:/var/lib/postgresql/data]
    ports: ["5432:5432"]

  redis:
    image: redis:7
    ports: ["6379:6379"]

  api-gateway:
    build: { context: ../.., dockerfile: infra/docker/api-gateway.Dockerfile }
    env_file: ../../.env.local
    ports: ["8080:8080"]
    depends_on: [postgres, redis]

  agent:
    build: { context: ../.., dockerfile: infra/docker/agent.Dockerfile }
    env_file: ../../.env.local
    depends_on: [postgres, redis]

  perception:
    build: { context: ../.., dockerfile: infra/docker/perception.Dockerfile }
    env_file: ../../.env.local
    devices: []   # Mac 摄像头不能直通容器，C 在 Mac 阶段用 host 模式或本地起服务
    depends_on: [postgres, redis]

volumes: { pgdata: {} }
```

### 8.2 Mac 摄像头限制
- Docker Desktop on Mac 不能直通 USB / 摄像头。
- 解决：C 的 perception 服务在 Mac 阶段**直接用 host 进程**跑（`uv run uvicorn`），不进容器。
- compose 里给一个 profile `--profile no-perception`，A 和 B 用 compose，C 自己 host。

### 8.3 一键命令

```makefile
# Makefile
.PHONY: dev up down test bootstrap

bootstrap:
	pnpm install
	uv sync --all-packages
	cp -n .env.example .env.local || true
	docker compose -f infra/compose/docker-compose.yml up -d postgres redis
	uv run alembic upgrade head
	uv run python infra/scripts/seed_dev_data.py

dev:
	docker compose -f infra/compose/docker-compose.yml up

down:
	docker compose -f infra/compose/docker-compose.yml down

test:
	pnpm -r test
	uv run pytest

contract-test:
	docker compose -f infra/compose/docker-compose.test.yml up -d
	uv run schemathesis run packages/contracts/openapi.yaml --base-url http://localhost:8080
	docker compose -f infra/compose/docker-compose.test.yml down
```

## 10. 安全（必须做的）

### 10.1 依赖
- `pnpm audit` + `pip-audit` weekly
- 高危漏洞 24h 内修

### 10.2 输入校验
- 所有 endpoint 用 pydantic 校验
- 上传：限大小（默认 100MB）、限扩展名、限 Content-Type、内容嗅探（python-magic）
- 解压防护：zip-slip 路径校验、解压总大小上限（防 zip bomb）
- URL 输入（RSS）：SSRF 防护，禁内网网段 + DNS rebinding 防护

### 10.3 JWT / Cookie
- HttpOnly + Secure + SameSite=Strict cookie 存 refresh token；access token 走 Authorization header
- CSRF token 用 double-submit cookie

### 10.4 LLM / Skill 安全（与 B 协作）
- Skill 风险白名单 + risk=high 二次确认
- prompt-injection 在 gateway 层先做粗筛（黑词库），细做交 B 的 safety/injection.py
- Skill 沙箱：Linux 阶段 nsjail；Mac 阶段 subprocess + RLIMIT

### 10.5 审计日志
- `audit_log` 表：所有"危险操作"（用户管理 / VM destroy / 共享区改动 / Skill risk=high）必须记录
- 字段：actor, action, target, payload_hash, ip, ts

### 10.6 备份与恢复
- pg_dump 每日 + 测试恢复（每月跑一次）
- 用户偏好和记忆数据明确保留期，用户可全部删除（GDPR 风格）

## 14. Mac→Linux 部署预案

### 14.1 关键差异表

| 维度 | Mac 阶段 | Linux 阶段 |
|---|---|---|
| 摄像头 | host 进程（非 docker） | docker + `--device /dev/video0` 或 host |
| GPU | 无（mock） | NVIDIA Container Toolkit + `--gpus all` |
| 串口 | mock | `--device /dev/ttyUSB0` |
| 屏幕方向 | mock | xrandr / wlr-randr in-host |
| LLM | 云 MiniMax | 云 + llama.cpp 兜底 |
| Compose | docker-compose.yml | docker-compose.prod.yml |
| 反代 | 直连 8080 | Nginx + HTTPS |
| 备份 | 手动 | cron + NAS |

### 14.2 部署脚本（草案）

```bash
# infra/scripts/deploy-linux.sh
set -euo pipefail
git fetch origin && git checkout "$1"
docker compose -f infra/compose/docker-compose.prod.yml pull
uv run alembic upgrade head
docker compose -f infra/compose/docker-compose.prod.yml up -d
./infra/scripts/healthcheck.sh
```
