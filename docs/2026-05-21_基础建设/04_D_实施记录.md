### D1.5: SSE keepalive 心跳真注入

**日期**：2026-05-21  
**文件**：`services/api-gateway/app/proxy/forward.py:133-172`

#### 改动

将 `_stream_sse` 中的 TODO 替换为 `asyncio.wait_for` + `TimeoutError` 驱动的 keepalive 注入：

- 使用 `asyncio.wait_for(stream.__anext__(), timeout=15)` 等待上游数据
- 若 15s 内无数据 → 捕获 `asyncio.TimeoutError` → yield `b": keepalive\n\n"`
- 若上游数据到达 → yield 数据 chunk
- 若客户端断开 (`request.is_disconnected()`) → break 停止流
- 若上游流结束 (`StopAsyncIteration`) → break

#### 常量

```python
_KEEPALIVE = b": keepalive\n\n"
_KEEPALIVE_INTERVAL = 15  # seconds
```

#### 测试覆盖

`tests/D/unit/test_sse_keepalive.py` (6 tests, all pass):
- `test_keepalive_injected_on_timeout` — `wait_for` 第 2 次调用 raise TimeoutError → keepalive 注入
- `test_no_keepalive_when_no_timeout` — 无超时 → 无 keepalive
- `test_multiple_keepalives_on_repeated_timeouts` — 3 次连续超时 → 3 个 keepalive
- `test_keepalive_format` — 验证 keepalive 是合法 SSE comment（`:` 开头）
- `test_client_disconnect_stops_stream` — disconnect 后流终止
- `test_empty_stream_keepalive_loop` — 空流持续 keepalive 直到结束

测试策略：使用 `monkeypatch` 替换 `asyncio.wait_for` 精确控制 TimeoutError 抛出时机，避免真实 15s 延迟。

#### 已知问题

- `asyncio.wait_for` 取消内部协程时触发 `RuntimeWarning: coroutine was never awaited` — 无害，是正常行为（真实 httpx 流超时同理）
